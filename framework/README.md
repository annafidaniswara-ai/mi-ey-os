# Developmental Competency Framework

**Status: Draft — not reviewed or approved.**

## Scope

Define movement-learning competencies and observable indicators for MI-EY OS. The platform is intended for ages 2–6; the first framework tranche focuses on ages 2–4. Age ranges are contextual prompts, not universal milestone deadlines.

## Current draft documents

- [Developmental Competency Framework 2–4 — structure](developmental-competency-framework-2-4.md): proposed three core domains, integrative competencies, and framework design principles.
- [Competency Dictionary 2–4](competency-dictionary-2-4.md): detailed draft records with observable examples, non-examples, flexible progression options, adaptations, safety notes, cross-domain links, interpretation limits, and review criteria.
- [Competency Review Matrix 2–4](competency-review-matrix-2-4.md): draft reviewer rubric and tracking matrix; educator, safety/inclusion, and research review remain pending.
- [Fictional Instructor Walkthroughs 2–4](instructor-walkthroughs-2-4.md): three desk-based examples for testing the clarity of observations, adaptations, safety notes, and cross-domain links; not field-tested.

## Planned outputs

- Domain definitions and competency clusters.
- Observable indicators and flexible progression opportunities.
- Examples, non-examples, and adaptation guidance.
- Safety, inclusion, and evidence notes.
- Competency-level review rubric and version history.

## Quality requirements

Do not present age bands as universal milestones. Distinguish research evidence from instructional choices, cite credible sources, and avoid diagnostic language. Use fictional examples only in this public repository. Qualified educators must review developmental framing, safety, inclusion, and usability before operational use.

## Inputs and dependencies

Vision, design principles, architecture, research review, content model, and Product Owner review of the framework structure.

## Approval gate

Both documents remain Draft. A GitHub commit records a file change; it does not approve the framework. Only the Product Owner can approve project status after relevant review.
